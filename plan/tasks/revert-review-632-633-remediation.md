## Decisiones y límites

- La opción de recuperación es explícita: la aplicación normal continúa fallando cerrada ante contenido MCP divergente y no muta el journal.
- La preservación atómica de ownership/ACL de `.gitignore` tiene prioridad sobre un fallback in-place que pueda cambiar la semántica de hard links o dejar contenido parcial.
- Los proyectos que comparten un MCP global deben usar el mismo `AGENTSYNC_DATA_DIR` para compartir locks por path; diferentes overrides no coordinan entre sí (#635 queda fuera de este cambio y la limitación está documentada).
- `clean` enumera y elimina los hijos usando el directorio-capacidad no-follow retenido. Aun así, existe una ventana de último componente: un proceso concurrente puede sustituir el hijo entre la inspección symlink y el unlink relativo, pudiendo borrar un archivo normal. `revert` vuelve a paths después de enumerar por handle, así una sustitución entre revalidación y mutación puede redirigir la operación. Se documentan como límites de concurrencia por confirmar; no confundirlos con la carrera MCP fuera de alcance de #635.
- La ruta de permisos de directorios staged usa paths dentro de un `TempDir` privado (`0700` en Unix) para no retener un descriptor por directorio. Una interferencia de otro proceso del mismo UID no está aislada por esos permisos; un revisor la señaló como riesgo.
- La carrera MCP compare-then-persist de #635 permanece fuera de esta remediación; los límites de concurrencia documentados no se presentarán como resueltos.
- No se asumirán como resueltos hilos automáticos solo porque un commit marque “fixed”; resolver estado de GitHub requiere autorización separada.
- Riesgos revisados pero no resueltos en esta ronda: la raíz ya se snapshottea y verifica contra el no-follow component walk, pero una sustitución anterior a adquirir el primer snapshot no puede distinguirse del root elegido por path; el último componente de clean puede cambiar entre verificación de quarantine y unlink por nombre aleatorio; `revert` vuelve a paths tras enumerar por handle; y procesos del mismo UID maliciosos pueden manipular staging/quarantine, fuera del contrato de proceso normal. Además, el reemplazo `.gitignore` de Windows preserva DACL pero no SID propietario, y la mutación MCP por path conserva una ventana para writers externos. No se declaran cerrados por esta ronda.
